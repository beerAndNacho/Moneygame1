# V2 구현 명세

## 목표

1차 버전의 짧은 회수 미니게임을 장기 운영 가능한 통발 경제 게임으로 확장한다. 사용자는 설치한 통발을 기다렸다가 회수하고, 어획물을 시장 상황에 맞춰 처분하며, 선박 설비를 성장시킨다.

## 상태 흐름

```text
empty → sinking → catching → ready → stale → retrieving → completed
```

- 설치 시 통발의 `deployedAt`, `readyAt`, 결과 시드를 저장한다.
- 상태는 현재 시각과 저장된 시각으로 계산되므로 브라우저 종료 중에도 진행된다.
- 설치 시 생성된 시드로 어획 후보가 결정되어 새로고침 반복으로 결과를 바꾸기 어렵다.
- 회수 플레이의 판정과 장비 보너스가 최종 수량·크기·품질을 보정한다.

## 저장 마이그레이션

`migrateState()`가 저장 스키마의 누락 필드를 초기값과 병합한다. V1의 레벨, 조개, 도감, 장비와 주요 누적 기록은 V2 구조로 변환된다. 손상된 저장 데이터는 초기 상태로 안전하게 복구된다.

## 경제

- 섬마을: 시세 변동이 적고 운송비가 없는 안정적인 판매처
- 도시 시장: 날짜별 카테고리 시세를 반영하며 잠재 가격이 높음
- 신선도: 시간 경과로 감소하며 냉장고 레벨이 감소 속도를 낮춤
- 창고 초과분: 플레이가 막히지 않도록 섬마을 가격으로 자동 판매

## 회수 미니게임

회수 진행률에 따라 세 구간으로 변경된다.

1. 해저 이탈: 바위 걸림과 초기 장력 관리
2. 중층 회수: 이동 타이밍 구역과 위험 이벤트
3. 수면 돌파: 좁은 판정 구역과 높은 보상

장력·잠금·내구도가 임계값을 넘으면 완전 실패가 아니라 일부 어획물을 보존하는 부분 회수로 전환될 수 있다.

## 자동 테스트 범위

- 콘텐츠 최소 수량
- 설치 판정 경계
- 시간 기반 통발 상태
- 날짜·시드 기반 결정성
- 통발 용량 제한
- 부분 회수 보존 규칙
- 냉장고와 신선도
- 판매 채널별 가격
- 일일 의뢰 순환
- V1 저장 마이그레이션
- 설치→대기→회수→판매 통합 흐름
- 업그레이드 슬롯 제한
- PERFECT와 MISS의 기계적 차이
- 초기 상태 유효성
